# JOINING.md — 팀 합류(온보딩) 가이드 (범용)

> **사람이 읽는 가이드.** 에이전트 룰북·형식 명세가 아니라, *새 팀원이 이미 돌아가고 있는 AI-DLC 시스템에 합류* 하는 절차를 설명한다.
> 여기서 "합류"는 *신규 부트스트랩(시스템 최초 생성)이 아니라, 기존 팀 인스턴스를 공유 원격에서 clone 해 받는 것* 을 뜻한다. 이미 있는 시스템에 두 번째·세 번째… 사람이 들어오는 경우다.
> 트래커 종류·호스트·레포 이름·계정 값 등 *구체 좌표* 는 팀마다 다르다 — 이 문서는 *절차* 만 범용 용어로 설명하고, 실제 값(공유 원격 URL·자격증명 등)은 **팀에서 받아** 각자 채운다.
> 위치: `ai-dlc-orchestrator/docs/JOINING.md`

---

## 0. 합류 전 준비물 (팀에서 받아야 하는 것)

합류자는 시작 전에 아래를 팀(또는 시스템 소유자)에게서 받아야 한다. 이 값들은 *배포별* 이라 이 문서에 박지 않는다.

| 받을 것 | 왜 필요한가 | 비고 |
|---|---|---|
| **프레임워크 리포 URL** (`ai-dlc-orchestrator`) | 룰북·템플릿을 클론으로 받는다 | 공개/사내 공유 리포 |
| **시스템 인스턴스(메타 레포) 공유 원격 URL** | 팀의 오케스트레이터·레포 맵·사이클 로그를 clone 으로 받는다 (§2) | *합류의 핵심 입력* — 신규 생성이 아니라 이 URL로 clone |
| **자격증명 발급** (자기 몫) | git 커밋 정체성·트래커/원격 토큰 등 | 값은 각자 로컬에만(§4) — 발급·권한 부여는 사람 게이트 |
| **에이전트 런타임 + git** | 세션을 열고 부트스트랩을 돌린다 | OS 무관 |

> **핵심:** 합류자는 *메타 레포를 새로 만들지 않는다*. 팀에서 받은 **공유 원격 URL** 을 부트스트랩 인터뷰에 입력하면, 시스템이 "이미 존재함 → 합류(clone)" 로 자동 분기한다(§2). 그 URL을 팀에서 받는 것이 합류의 전제다.

---

## 1. 프레임워크 클론

프레임워크 리포(`ai-dlc-orchestrator`)를 클론하고, 에이전트 런타임에서 연다.

```sh
git clone <프레임워크-리포-URL>
cd ai-dlc-orchestrator
```

- 리포를 에이전트 런타임에서 열면 루트의 세션 진입점(`CLAUDE.md`)이 자동으로 읽혀 **오케스트레이터(팀장) 정체성** 을 부트스트랩한다. 갓 클론한 리포도 이 파일 하나로 자력 시작한다.
- 이 단계에서 받는 것은 *공유 룰북·템플릿*(Layer 0) 뿐이다 — 팀의 *인스턴스*(Layer 1)는 아직 없다. 그것은 §2에서 합류로 받는다.

---

## 2. 세션 시작 → 미부트스트랩 감지 → SETTER 합류(clone)

에이전트 세션을 시작하면 오케스트레이터가 부트스트랩 상태를 점검한다. *로컬에 시스템 인스턴스가 아직 없으므로* 미부트스트랩으로 판정하고 **`SETTER`** 를 서브 에이전트로 호출한다.

여기서 **합류자는 신규 생성이 아니라 합류(clone) 경로로 가야 한다.** 그 분기를 가르는 것은 SETTER 인터뷰의 *공유 원격 URL 질문* 이다:

1. SETTER가 메타 레포 위치·이름과 함께 **"시스템 인스턴스(메타 레포) 공유 원격 URL?"** 을 묻는다.
2. 여기에 **§0에서 팀으로부터 받은 공유 원격 URL** 을 입력한다.
3. SETTER는 그 원격에 *인스턴스가 이미 있음* 을 감지하고 → **합류(clone)** 로 분기한다. 이때:
   - 팀의 오케스트레이터 인스턴스·레포 맵·사이클 로그를 **clone 으로 그대로 받는다** (팀원이 이미 채운 상태).
   - **인스턴스를 재생성하지 않는다** — 팀원 것을 덮어쓰지 않기 위해 인스턴스 생성 단계는 스킵된다. (자격증명 셋업은 합류도 수행 — §4.)

> **왜 clone 인가:** 시스템 인스턴스는 *팀 공유* 산출물이다. 첫 사람의 최초 부트스트랩이 원격을 만들고, 이후 합류자는 그 원격을 clone 해 **하나의 단일 원천을 공유** 한다. 합류자가 새로 만들면 팀과 분리된 별개 시스템이 생겨 버린다 — 그래서 *반드시 팀의 공유 원격 URL* 로 clone 한다.

---

## 3. 레포별 셋업 (REPO-SETTER) + 대상 레포 clone

인스턴스를 받았으면(§2), 이제 *실제 작업할 레포들* 을 로컬에 준비한다. 합류자도 이 단계는 그대로 수행한다 — 레포 로컬 체크아웃·`.claude/` 셋업은 *머신별* 이기 때문이다.

- 오케스트레이터가 각 대상 레포에 대해 **`REPO-SETTER`** 를 호출해 로컬 레포의 `.claude/` 를 셋업한다(레포별 룰셋·Extension 설치 포함).
- 대상 레포 자체는 **레포 맵(REPO-MAP)에 기록된 *원격 URL* 에서 clone** 한다. 레포 맵은 머신 독립을 위해 *로컬 절대 경로가 아니라 원격 URL* 을 식별자로 저장하므로, 합류자는 자기 머신에 그 원격을 clone 하고 로컬 경로로 해석한다.
- 셋업 순서는 오케스트레이터가 판단한다(대개 의존 root 에 가까운 레포부터).

> 요약: **인스턴스는 clone 으로 받고(§2), 각 대상 레포도 레포 맵의 원격에서 clone 하며(§3), REPO-SETTER 가 로컬 `.claude/` 를 붙인다.** 공유되는 것은 *추적된 인스턴스·룰* 이고, 머신마다 새로 하는 것은 *로컬 체크아웃·셋업* 이다.

---

## 4. 자격증명 / 정체성 로컬 설정 (각자)

시크릿과 정체성은 *머신별·개인별* 이다 — 추적 파일(공유되는 인스턴스 포함)에 값을 올리지 않는다. 합류자는 자기 것을 로컬에 설정한다.

1. **시크릿 값 채우기**: 인스턴스에는 *필요한 시크릿 키의 매니페스트*(값 없는 예시 파일)만 공유돼 있다. 합류자는 그 매니페스트를 자기 로컬 시크릿 파일(예: `.env`)로 복사하고 **자기 값** 을 채운다.
   - 채우는 값 예(범용): 원격 호스팅 토큰, 디자인/외부 도구 키, 워크스페이스 루트 경로, (트래커 운영 시) 트래커 API 토큰 등.
   - 이 시크릿 파일은 *추적 제외*(gitignore) 되어 있어야 한다 — 값이 절대 공유 원격에 올라가지 않는다.
2. **git 커밋 정체성 설정**: 자기 이름·이메일로 커밋 정체성을 설정한다. *합류자 본인의 기여가 자기 이름으로 귀속* 되어야 한다(per-user attribution — 커밋 author·트래커 actor·MR 생성자가 본인).

> **자격증명 경계(사람 게이트):** 에이전트는 시크릿을 *읽고 사용* 만 한다. **토큰 발급·회전, 레포/트래커 접근 권한·멤버십 부여는 사람이 선결** 한다(자동 경로 밖). 그래서 §0에서 *발급* 을 받아 와야 하고, 여기서는 *로컬 배치* 만 한다.

---

## 5. 이후 운영 — 인스턴스에 담긴 규칙을 오케스트레이터가 자동 적용

합류가 끝나면(§1~§4), 일상 운영은 *합류자가 규칙을 따로 외울 필요 없이* 오케스트레이터가 자동으로 처리한다.

- 합류자는 오케스트레이터에게 **자연어로 지시** 만 하면 된다 — 인텐트 분류·영향 범위 분석·서브 호출·통합·검증은 오케스트레이터가 조율한다(사용자는 *오케스트레이터하고만* 대화).
- 팀 인스턴스에 담긴 규칙(공유 컨벤션, 누적된 학습, 트래커 운영 시 사이클↔티켓 바인딩, 다중 사용자 재귀 운영 시 완료 규율·로컬 리뷰-머지-학습 루프 등)이 *그대로 적용* 된다 — 이 규율의 methodology 원천은 프레임워크 명세(예: 사이클↔티켓은 `specs/ISSUE-TRACKER-ADAPTER.md`, 재귀 디스패치·완료 규율·학습 루프는 `agents/orchestrator/RECURSIVE-DISPATCH.md`)에 있고, *구체 좌표* 는 clone 으로 받은 인스턴스가 특화한다.
- 작업 전에는 항상 *관련 레포·인스턴스를 최신화(pull)* 한다 — 팀·병렬 세션의 갱신을 반영해 stale 위에 작업하지 않기 위함이다(공통 정책 — git fetch/pull 선행).

## 부록 A. 신규 부트스트랩 vs 합류 — 한눈에

| 구분 | 신규 부트스트랩 (첫 사람) | **합류 (이 문서 — 이후 팀원)** |
|---|---|---|
| 시스템 인스턴스 | *생성* (인터뷰로 채워 새로 만듦) | **clone** (팀 공유 원격에서 받음 — 재생성 안 함) |
| 트리거 | 로컬·원격에 인스턴스 없음 | 팀의 공유 원격 URL 입력 → "이미 존재" 감지 |
| SETTER 인스턴스 생성 단계 | 수행 | **스킵** (팀원 것 보존) |
| 레포별 REPO-SETTER + 대상 레포 clone | 수행 | **수행** (머신별이라 동일) |
| 자격증명·정체성 로컬 설정 | 수행 | **수행** (개인별이라 동일) |
| 이후 운영 | 오케스트레이터 자동 적용 | 오케스트레이터 자동 적용 |
