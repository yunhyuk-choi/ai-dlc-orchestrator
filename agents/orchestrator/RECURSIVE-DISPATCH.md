# RECURSIVE-DISPATCH.md — 재귀 디스패치 + 로컬 리뷰-머지-학습 루프 (범용 methodology)

> **이 문서는 형식·룰 명세 문서.** 에이전트 룰북 아님.
> 오케스트레이터의 *재귀 채널 E/F*(`agents/orchestrator/ORCHESTRATOR-AGENT.md` §3.1 채널 E 입력 / §3.2 채널 F 출력 — "본격 명세는 Stage 3+")의 본격 명세다. 상위 오케스트레이터가 하위(사용자별) 오케스트레이터에게 작업을 지시하는 *재귀 디스패치* 와, 그 지시가 로컬에서 리뷰·머지·학습으로 닫히는 *루프* 를 정의한다.
> 본 명세는 **룰만** 정의한다 — 실행은 오케스트레이터(상위·하위 양측)와 그 서브 에이전트(특히 `ISSUE-TRACKER-AGENT`·`CYCLE-CLOSER`)가 수행한다.
> 본 명세는 **조건부** 다 — 재귀 확장(상위 오케스트레이터 존재)과 이슈 트래커 운영을 전제로만 발동한다(§1). 단일 사용자·트래커 미운영 시스템에서는 비활성(inert)이다.
> **프레임워크(범용) methodology** — 트래커 종류·필드·URL·계정 식별자 등 *구체 좌표* 는 여기 박지 않는다. 그것들은 **인스턴스**(Layer 1)가 특화한다(§7 Layer 경계).

> 위치: `ai-dlc-orchestrator/agents/orchestrator/RECURSIVE-DISPATCH.md`

> **POLICY-RECURSIVE-DISPATCH (재귀 디스패치 + 로컬 완료 규율)** — 상위(중앙) 오케스트레이터가 이슈 트래커를 감시해 담당자별로 작업을 매핑하고, 각 담당자의 하위(사용자별) 오케스트레이터에게 채널 E/F로 지시한다. **하위는 그 담당자의 계정·정체성으로 자율 실행하되, 티켓을 '완료(Done)'로 전이하지 않는다** — 자율 실행은 *MR 초안 + 티켓 '진행 중'(리뷰 대기)* 로 종료하고, **완료는 로컬 오케스트레이터가 MR을 리뷰·교정·머지하는 시점에** 이뤄진다(트래커가 요구하는 필드 충족 포함). **학습은 사람 교정이 있는 로컬 루프에서만** 인스턴스의 학습층에 distill되며(자율 실행은 학습층 read-only), **자율 실행은 새 티켓을 만들지 않는다**(트리거 티켓 = 작업 티켓). 커밋 author·트래커 actor·MR 생성자는 *담당 사용자* 로 귀속한다(per-user attribution).

### 1.1 적용 조건 (발동 vs 비활성)

본 명세는 **다음 둘이 모두 성립할 때만** 발동한다 — 추정하지 않고 인스턴스/런타임에서 확인한다.

| 전제 | 확인 신호 |
|---|---|
| **재귀 확장** — 상위 오케스트레이터가 존재해 하위에게 채널 E로 지시한다 | 채널 E 입력이 *상위 오케스트레이터* 출처(사용자 직접 입력 아님) |
| **이슈 트래커 운영** — 감시 대상 티켓·담당자 매핑이 가능하다 | 인스턴스에 트래커 config 존재(POLICY-ISSUE-TRACKING 발동 — `specs/ISSUE-TRACKER-ADAPTER.md` §1.1) |

**둘 중 하나라도 없으면 비활성(inert)** — 단일 사용자 시스템(상위 없음)이거나 트래커 미운영이면 본 재귀 루프를 적용하지 않는다. 기존 채널 A(사용자 직접)·책임 7(사이클↔티켓) 경로만 동작한다.

## 2. 역할 계층 (상위 / 하위)

```
        이슈 트래커 (감시 대상 — 담당자 필드가 진실의 원천)
             │  감시 · 담당자 매핑
             ▼
   상위(중앙) 오케스트레이터        ← 재귀 디스패처. 티켓 → 담당자 → 하위 지시
   ┌─────────┼─────────┐
   ▼         ▼         ▼
 하위 O.    하위 O.    하위 O.       ← 사용자별 로컬 오케스트레이터
 (사용자a)  (사용자b)  (사용자c)       각자의 계정·정체성으로 자율 실행 + 로컬 루프
```

| 역할 | 정체성 | 책임 |
|---|---|---|
| **상위(중앙) 오케스트레이터** | 시스템 감시자 | 트래커 감시 → 담당자 매핑 → 채널 E로 하위 디스패치. *하위의 티켓을 대신 완료 전이하지 않는다*(완료는 담당 사용자의 로컬 루프 몫). |
| **하위(사용자별) 오케스트레이터** | *담당 사용자* 의 계정·정체성 | 지시받은 티켓을 자율 실행(§4 모드 A/B) → MR 초안 + 티켓 '진행 중'까지. 이후 그 사용자의 로컬 리뷰-머지-학습 루프(§5)로 완료. |

- **디스패치 판단(직렬/병렬)은 상위 오케스트레이터 책임 3** 에 귀속한다 — 담당자·영향 범위가 겹치지 않는 티켓은 병렬 디스패치, 생산자→소비자 의존이 있으면 직렬(ORCHESTRATOR-AGENT 책임 3 / DECISIONS A-5 정합).
- **per-user attribution(§6)**: 하위가 만든 커밋 author·트래커 actor·MR 생성자는 *그 담당 사용자* 로 귀속한다 — 상위(중앙)나 봇 정체성이 아니다.

## 3. 재귀 디스패치 절차 (상위 → 하위)

```
[RD1] 트래커 감시        상위가 트래커를 폴링/구독 — 담당자 배정된·미착수 티켓 감지
   ↓
[RD2] 담당자 매핑        티켓의 담당자 필드 → 그 담당자의 하위 오케스트레이터 정체성
   ↓
[RD3] 직렬/병렬 판단      영향 범위·의존으로 클러스터링 (책임 3 / DECISIONS A-5)
   ↓
[RD4] 채널 E 디스패치     하위에게 작업 지시 — 트리거 티켓 키·범위·자율 모드(§4)를 컨텍스트로 전달
   ↓
[RD5] 채널 F 수신         하위가 결과(§4 종료 상태 — MR 초안 + '진행 중')를 상위에 응답
   ↓
[RD6] 집계·보고           상위는 담당자별 진행을 집계 — 단, 완료 전이는 하지 않음(§ 완료 규율)
```

- **RD4 지시 컨텍스트(최소 정보 — 채널 B 표준 정합)**: (트리거 티켓 키·URL / 범위 경계 / 자율 모드 A|B / 관련 링크). 하위는 이 티켓을 *작업 티켓* 으로 삼는다(§ 루프 방지 — 새 티켓 생성 금지).
- **RD5 채널 F 응답 형식**: 채널 A와 대칭(ORCHESTRATOR-AGENT §3.2 F) — (산출물: MR 초안 URL·브랜치 / 티켓 상태: '진행 중'(리뷰 대기) / 저널·다음 단계).
- 상위는 하위의 *자기 보고* 를 클레임으로 취급한다 — 통합·상위 보고 전 지상검증(POLICY-VERIFY) 원칙은 재귀 경계에서도 유지된다.

## 4. 자율 모드 A / B (사용자별 선택)

하위 오케스트레이터의 자율 실행 깊이는 *담당 사용자* 가 선택한다(인스턴스 config에 사용자별로 기록 가능 — Layer 1). 어느 모드든 **완료 규율(§ 아래)은 불변** 이다.

| 모드 | 이름 | 자율 실행이 하는 일 | 종료 상태 |
|---|---|---|---|
| **A** | 완전 자율 | 트리아지 → 브랜치 → 구현 → **코드 + MR 초안까지** | MR 초안 + 티켓 '진행 중'(리뷰 대기) |
| **B** | 경량 1차 | 트리아지 → 브랜치 → **스캐폴딩 + 최소 시도** + **저널**(맥락·시도·막힌 지점 기록) | 브랜치 + (있으면 부분 MR 초안) + 티켓 '진행 중'. **실질 완성은 로컬 사람 루프**(§5) |

- **모드 B의 저널**: 무엇을 시도했고 어디서 막혔는지, 사람이 이어받을 지점을 남긴다 — 로컬 루프(§5)의 입력이 된다.
- 모드 선택은 *신뢰·리스크* 트레이드오프다: A는 리뷰 부하를 뒤로 미루고(초안 완성도↑), B는 사람 주도를 앞세운다(자율 표면↓). **어느 쪽도 티켓을 완료로 전이하지 않는다.**

### ⚠️ 완료 규율 (핵심 — 모드 불변)

> **자율 실행은 티켓을 '완료(Done)'로 전이하지 않는다.**
> 자율 실행의 종료점은 **MR 초안 + 티켓 '진행 중'(리뷰 대기)** 이다. **완료(Done) 전이는 오직 로컬 오케스트레이터가 MR을 리뷰·교정·머지하는 시점에** 수행한다(§5) — 이때 *트래커가 요구하는 필드 충족* 도 함께 성사시킨다(POLICY-ISSUE-TRACKING §3.2 CLOSE / §6 필수 필드).

- 근거: 사람 교정이 없는 자율 산출을 완료로 선언하면 *클레임이 증거를 앞선다*(POLICY-VERIFY 위배). 리뷰·머지라는 **사람 게이트가 완료의 유일한 성사 지점** 이다.
- 자율 실행 중 In-Progress 전이는 정상(POLICY-ISSUE-TRACKING §3.2 START — 사이클 시작 시 필수). *금지되는 것은 Done 전이뿐* 이다.

## 5. 로컬 리뷰-머지-학습 루프 (하위 오케스트레이터가 자동으로 따르는 절차)

> 리뷰 태스크를 수신하면 하위(로컬) 오케스트레이터는 아래 순서를 **명시적 단계로, 하나도 빠뜨리지 않고** 따른다. 특히 **[L4] 학습 distill 과 [L5] 인스턴스 push 를 [L6] 머지·[L7] 완료 전이 앞에 두는 순서** 를 지킨다(학습·공유가 완료보다 앞서야 유실되지 않음).

```
[L1] 리뷰 태스크 수신        사람(담당 사용자)이 MR 초안에 리뷰 요청/코멘트
   ↓
[L2] 인스턴스·설계문서 PULL   git fetch/pull 선행 — 인스턴스(Layer 1)와 관련 설계 문서 최신화
   ↓
[L3] 리뷰 반영 (코드 수정)    사람 교정을 코드에 반영 (하위가 실행)
   ↓
[L4] 학습 DISTILL·기록        이번 교정에서 얻은 *일반화된 교훈* 을 인스턴스의
                             사용자별 학습 저장소(학습층)에 distill·기록 (§ 학습 불변식)
   ↓
[L5] 인스턴스 PUSH            갱신된 인스턴스(학습층 포함)를 공유 원격에 push
   ↓
[L6] MR 머지                 리뷰 통과한 MR을 머지
   ↓
[L7] 티켓 완료 전이           **그 시점에** 트래커 필수 필드 충족 + Done 전이 (CYCLE-CLOSER)
```

- **[L2] pull 선행**: 병렬 세션·다른 담당자의 갱신을 반영해야 stale 위에 작업하지 않는다(공통 정책 — git fetch/pull 선행).
- **[L4] 학습 distill**: 교정을 *이번 티켓 한정 수정* 이 아니라 *재사용 가능한 일반화* 로 증류해 인스턴스 학습층에 남긴다. 적용처·형식은 `specs/EVOLUTION.md`(신호 ⑤ 회고·②③④ 반복 등)에 따르며, **적용 대상은 인스턴스(Layer 1)뿐** — 공유 룰북(Layer 0)은 자동 경로가 건드리지 않는다(EVOLUTION §D-Stage3-6).
- **[L5] push before [L6] merge/[L7] Done**: 학습·인스턴스 갱신이 *완료보다 먼저 공유* 되어야 팀·후속 사이클이 그 학습을 즉시 활용한다. 순서가 뒤집히면 학습이 로컬에 잔존·유실될 위험이 있다(SETTER S8.6 "커밋 성사 검증" 정신과 정합).
- **[L7] 완료 전이 = 유일한 Done 지점**: §4 완료 규율의 성사점. Done 전이는 `CYCLE-CLOSER`의 외부 액션으로 수행(POLICY-ISSUE-TRACKING §3.2 CLOSE / §5 CLOSE 전이 주체)하며, 트래커가 요구하는 필드(예: 완료 사유·해결책 등)를 함께 충족한다.

## 6. 루프 방지 & per-user attribution

### 6.1 루프 방지 (트리거 티켓 = 작업 티켓)

- **자율 실행은 새 티켓을 생성하지 않는다.** 상위가 디스패치한 *트리거 티켓* 이 곧 *작업 티켓* 이다 — 하위는 그 티켓 위에서 In-Progress 전이·코멘트·MR 배선을 수행한다(POLICY-ISSUE-TRACKING §3.2·§3.3 작은 후속 재사용과 정합).
- 이 규율이 없으면 *감시 → 티켓 생성 → 그 티켓이 다시 감시에 걸림 → 또 생성* 의 **자가 증식 루프** 가 생긴다. 트리거=작업 동일성이 그 고리를 끊는다.
- *범위 밖* 개발 아이템(다른 담당자·다른 소유 영역)이 필요하면, 그것은 새 *요청 티켓* 으로 발행하되 **자기 전이하지 않고 트리아지/소유자에게 배정** 한다(POLICY-ISSUE-TRACKING §3.1 (A)) — 이는 자율 실행의 산출물·핸드오프이지 자기 증식이 아니다.

### 6.2 per-user attribution

- **커밋 author · 트래커 actor(전이·코멘트 수행자) · MR 생성자 = 담당 사용자.** 하위 오케스트레이터는 *그 사용자의 정체성* 으로 동작하므로(§2), 산출물의 귀속이 실제 담당자와 일치한다.
- 상위(중앙) 오케스트레이터·공용 봇 정체성으로 커밋/전이하지 않는다 — 감사 추적·리뷰 책임·기여 이력이 사람 단위로 유지되어야 한다(POLICY-TRACKING 정합).
- 자격증명 경계: 각 하위는 *자기 사용자의* 시크릿 스토어(`.env`/토큰 파일 경로)에서 자격증명을 읽어 그 사용자로 인증한다 — 값은 추적 파일에 두지 않는다(자격증명 경계 / POLICY-ISSUE-TRACKING §8).

## 7. 학습 불변식 & Layer 경계

### 7.1 학습 불변식 (사람 교정 있는 로컬에서만)

- **학습층 쓰기는 로컬 사람 루프(§5 L4)에서만 일어난다.** *자율 실행(§4)은 학습층에 대해 read-only* 다 — 사람 교정이 없는 자율 산출은 학습으로 승격되지 않는다.
- 근거: 학습은 *검증된 교훈* 이라야 한다. 사람 리뷰·교정이라는 신호 없이 자율 산출을 학습하면 오류가 자기 강화된다. 리뷰-머지 루프의 교정이 유일한 학습 입력이다.
- 이는 EVOLUTION의 "공유 룰북 불가침 + 적용은 인스턴스에만"(D-Stage3-6)을 재귀 맥락으로 확장한 것이다 — *자율 vs 사람-교정* 축을 추가로 그어, 학습을 사람-교정 로컬 루프로 한정한다.

### 7.2 Layer 경계 (Layer 0 프레임워크 / Layer 1 인스턴스)

| Layer | 무엇 | 본 명세에서의 역할 |
|---|---|---|
| **Layer 0 — 프레임워크(범용)** | `ai-dlc-orchestrator` 공유 룰북·본 methodology | *어떻게* 재귀 디스패치·완료 규율·루프를 운영하는지의 **불변 룰**. read-only(자동 경로 불가침). |
| **Layer 1 — 인스턴스** | 시스템 인스턴스(예: 메타 레포)·사용자별 학습 저장소 | *구체 좌표* — 트래커 종류·필드·URL·계정 식별자·담당자↔하위 매핑·사용자별 자율 모드·학습층 내용. |

- 본 문서(Layer 0)는 **트래커 종류·필드·URL·계정 식별자를 절대 담지 않는다** — 그것들은 인스턴스(Layer 1)가 `specs/ISSUE-TRACKER-ADAPTER.md`의 config 계약(§2)을 통해 특화한다.
- 상위↔하위 매핑(담당자 → 그 사용자의 하위 오케스트레이터 정체성)과 사용자별 자율 모드(A/B) 역시 *인스턴스* 데이터다 — 프레임워크는 그 *형태* 만 규정한다.

## 변경 이력

본 명세 v1.0 — **POLICY-RECURSIVE-DISPATCH 신설**: 채널 E/F(재귀)의 Stage 3+ 본격 명세. 상위(중앙)→하위(사용자별) 재귀 디스패치(트래커 감시→담당자 매핑→직렬/병렬→채널 E 지시→채널 F 수신), 자율 모드 A(완전 자율)/B(경량 1차), **완료 규율**(자율 실행은 Done 전이 금지 — 완료는 로컬 리뷰·교정·머지 시점), 로컬 리뷰-머지-학습 루프(pull→리뷰 반영→학습 distill→인스턴스 push→머지→완료 전이의 고정 순서), 루프 방지(트리거 티켓=작업 티켓·새 티켓 금지)·per-user attribution(커밋/actor/MR=담당 사용자), 학습 불변식(사람 교정 로컬에서만·자율은 학습층 read-only), Layer 0(프레임워크)/Layer 1(인스턴스) 경계.

근거: 채널 E/F가 예약만 되고 "본격 명세 Stage 3+"로 비어 있어, 다중 사용자·재귀 운영에서 *누가 언제 완료 전이하고 학습하는지* 의 규율이 없었다. 본 명세가 그 층을 *범용·조건부* 로 채운다(단일 사용자·트래커 미운영 시 비활성). 구체 좌표는 인스턴스가 특화한다.

향후 변경은 깃 PR/머지 (원칙 8).
